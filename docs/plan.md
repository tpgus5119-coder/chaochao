# 베트남어 스터디 앱 — 기획서 v1 (2026-08-20)

## 0. 한 줄 정의
> **동기 몇 명이 매일 15분씩, 같은 단어 10개와 문형 틀 2개를 배우고
> 그걸로 서로 대화하게 만드는 웹페이지.**

## 1. 확정된 전제 (사용자 결정)
| 항목 | 결정 |
|---|---|
| 목적 | **업무 — 생산·제조 현장 중심** (+ 일상 표현 보조) |
| 발음 기준 | **북부(하노이) 기본 + 남부 음성 병기** |
| 진도 | **신규는 전원 공통 / 복습은 개인 자율** |
| 하루 분량 | 단어 10개 + 문형 틀 2개 |
| 결과물 | 앱 아닌 **웹** (폰·PC 공용) |
| 범위 | **완성도 높은 앱 아님. 간단·심플 기능만** |

## 2. 조사에서 나온 설계 근거 (요약)
자세한 근거는 `research-textbooks.md`.

1. 국내 초급 교재 5종 + 국가 표준 교재의 **목차 순서가 사실상 동일** → 그대로 뼈대로 쓴다.
2. **모든 교재·기관이 1과(또는 Day 0)를 문자·성조에 통째로 쓴다** → Day 0 필수.
3. 국내 1위 교재(GO! 독학)가 **북부 본문 + 남부 발음 별도 제공** → 우리 결정과 일치.
4. 초중급 회화를 233패턴이 커버 → **A1은 틀 40~60개면 충분**. 틀 1개당 예문 5개가 시장 밀도.
5. **생산·제조 현장 초급 교재는 시장에 없다** → 여기가 우리 자리.
6. 현지 최대 기관 USSH 기준 **A1 = 80시간**. 하루 15분×주5일이면 A1까지 약 15개월.
   → 앱은 어휘·발음·복습 담당, 나머지는 대화 미션이 벌충.

## 3. v1 기능 — 딱 5개만 만든다

### ① 오늘의 카드
- 단어 10개 + 문형 틀 2개
- 카드 앞면: **베트남어 철자(성조 부호 포함)** + 🔊 버튼
- 카드 뒷면: 한국어 뜻 + 한자어 힌트(있을 때만)
- **한글 독음은 기본 숨김**, 탭하면 열림. 14일 뒤 자동으로 안 나옴

### ② 소리
- 단어·예문마다 MP3. **북부 기본 / 남부 토글** 1개
- 미리 만들어 둔 정적 파일. 재생만 함. 녹음·채점 없음

### ③ 복습 퀴즈
- 문제 유형 2개뿐: **듣고 고르기**(4지선다), **뜻 고르기**(4지선다)
- 간격은 단순 4단계: 맞추면 `1일 → 3일 → 7일 → 14일`, 틀리면 1일로 복귀
- 복습은 개인 자율 (기기에만 저장)

### ④ 오늘의 대화 미션
- 카드 1장. 앱은 **보여주기만** 한다 (채팅 기능 없음 — 대화는 단톡방에서)
- 형식: 역할 A/B + 써야 할 틀 + **정보차 과제**(상대만 아는 정보를 알아내기)

### ⑤ 진도 표시
- `Day 7 / 완료 ✔` 수준. 스트릭·랭킹·알림 전부 없음

### v1에서 안 만드는 것 (명시적으로 뺀다)
로그인·서버·계정 / 녹음·발음 자동채점 / 채팅 / 알림·푸시 / 스트릭·랭킹 /
문법 설명 페이지 / 쓰기 연습 / 진도 동기화

## 4. 만드는 방법 (기술)

```
베트남어-어플/
├─ index.html          ← 화면 전부 (한 파일)
├─ app.js              ← 로직 (카드/퀴즈/간격)
├─ style.css
├─ data/
│   └─ days.json       ← 커리큘럼 전체 (단어·틀·미션)
└─ audio/
    ├─ n/  (북부)
    └─ s/  (남부)
```
- **서버 없음.** 진도는 브라우저 `localStorage`에 저장
- 배포: GitHub Pages (무료, 링크만 공유하면 폰에서 바로 열림)
- 홈 화면에 추가하면 앱처럼 보임 (PWA는 v2에서)

### 데이터 형식 (days.json)
```json
{
  "day": 1,
  "theme": "인사",
  "words": [
    { "vi": "chào", "ko": "안녕", "kr_read": "짜오", "tone": "평성", "hanja": null,
      "audio": "d01_01" }
  ],
  "frames": [
    { "vi": "Chào {A}!", "ko": "{A} 안녕하세요!", "examples": ["Chào anh!", "Chào chị!"] }
  ],
  "mission": {
    "goal": "서로의 호칭을 정하라",
    "a": "당신은 27살입니다", "b": "당신은 31살입니다"
  }
}
```
JSON만 채우면 앱이 굴러간다. **코드는 한 번 만들고, 이후엔 데이터만 늘린다.**

## 5. 커리큘럼 (v1 = 4주치만 만든다)

| 구간 | 내용 | 단어 | 비고 |
|---|---|---|---|
| **Day 0** | 문자 · 성조 6개 · 발음 | — | 신규 단어 없음. 듣고 구분만 |
| Day 1~5 | 인사 / 호칭 / 이름 / 소개 | 50 | 호칭은 한국어와 같은 구조 → 유리 |
| Day 6~10 | 숫자 / 수량 / 시간 / 요일 | 50 | 현장 수량 표현의 기초 |
| Day 11~15 | **작업 지시 / 수량·불량** | 50 | 우리 고유 구간 |
| Day 16~20 | **안전 / 교대 / 설비·공구** | 50 | 우리 고유 구간 |

- 주 5일 신규 + 주 2일 복습 전용 → **4주 = 200단어 + 40틀**
- Day 11부터는 **새 문법을 얹지 않는다.** Day 1~10의 틀에 현장 어휘만 갈아끼운다
- 현장 어휘 선정은 KOSHA 한베 용어사전을 **참고만** 하고 직접 작성 (라이선스 §A-4)

## 6. 진행 순서

| 단계 | 할 일 | 산출물 |
|---|---|---|
| **1** | Day 0~5 데이터 직접 작성 (단어 50 + 틀 10 + 미션 5) | `days.json` 일부 |
| **2** | 음성 생성 (북부·남부 각 1세트) | `audio/` |
| **3** | 화면 만들기 (카드·퀴즈·미션·진도) | `index.html` 외 |
| **4** | GitHub Pages 배포 → 동기들에게 링크 | URL |
| **5** | **2주 실사용 후 판단** — 10개가 많은지 적은지 실측 | 조정 |
| 6 | Day 6~20 데이터 채우기 | — |

> 1~4단계가 v1이다. **콘텐츠가 일이지 코드가 일이 아니다.**

## 7. 잘 되고 있는지 재는 법 (간단히)
- 주 1회: **7일 이상 지난 단어**로 20문항 (오늘 배운 걸 오늘 재면 아무 의미 없음)
- 목표선: 20문항 중 **14개 이상**이면 분량 유지, 10개 미만이면 하루 7개로 줄임
